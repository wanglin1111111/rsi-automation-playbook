# 双层监控：覆盖率、审查延迟、升级率

## 为什么必须有监控：罕见事件会常态化

单个 Agent 失当目前罕见，但规模到百万、十亿级，**罕见就会变常态**。所以监控本身要用三个指标衡量：

| 指标 | 含义 | 反例（不合格） |
|---|---|---|
| 覆盖率 | 多少比例的动作/产物被监控触达 | 只盯不可逆动作，可逆动作零覆盖 |
| 审查延迟 | 从动作发生到被审查的时间 | 事后审查慢到"损害已不可逆"才审 |
| 升级率 | 多少监控命中升级到人工 | 升级率为 0 = 监控形同虚设（或阈值形同虚设） |

## Anthropic 运行数据（基准参照，2026-08）

- 最常用内部平台**任意时刻约 30,000 个 Agent** 在跑研发
- **在线监控器**：100% 事前拦截不可逆伤害（如拷走模型权重）
- **离线监控器**：100% 事后审查缓慢可逆风险
- 8 月逾 **10 亿次决策**中 0.002%（约 1/47,000）被拦截
- 每周约 **10 万份记录**，分类器初筛后约 **50 条**升级人工

## 最小可行动作（哪怕只有几个 Agent 也照做）

1. **不可逆动作清单**：删库、外发数据、付款、发布上线、改生产配置——逐项列出
2. **事前硬拦截**：清单内动作必须过前置检查（白名单/人工确认/二次验证），拦截失败=不许执行。这是硬规则，无豁免
3. **事后抽审**：可逆动作的产物，每周抽 1-2% 人工看一眼，记录：抽审量、发现问题数、拦截率
4. **三指标看板**：覆盖率（拦截清单覆盖多少动作类型）、审查延迟（发现到处置多久）、升级率（多少命中转人工）——每周更新一次
5. **拦截率是核心信号**：拦截率为 0 不是好消息，是"要么没风险要么没监控"——先区分这两种情况，再决定是放宽还是加严

## 双层结构

```
不可逆动作 ──→ 在线监控器（事前硬拦截，100% 覆盖）
可逆动作   ──→ 离线监控器（事后审查，全量记录+分类器初筛+抽样人工升级）
```

- 事前层保"不炸"，事后层保"缓慢的坏也能被抓"
- 分类器初筛是经济手段：全量人工审 10 万份/周不现实，初筛到 50 条/周才可持续
- 升级人工的判断标准要成文（什么特征触发升级），防止"分类器说了算"变成新的黑盒
